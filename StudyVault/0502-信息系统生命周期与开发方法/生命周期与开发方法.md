# 生命周期与开发方法

> [!info] 考情定位
> 讲义 p2 提要星级：**信息系统生命周期（★）、信息系统开发方法（★★）**。上午单选为主，考定义与阶段辨析。高频出题点：**生命周期四阶段 + 开发阶段五子阶段顺序、维护四类型的前后期分布、诺兰六阶段及各阶段特征、结构化方法四大特点与适用行业、原型法两种分类、自顶向下（结构化）vs 自底向上（面向对象）的定义判断、面向服务的抽象级别、形式化方法/净室**。讲义 p11 直接放了一道"软件方法学"真题（自顶向下/自底向上/形式化方法三定义）。

## 一、信息系统生命周期（四阶段）

讲义 p7 + 官方 §3.1.4：生命周期分为 **产生阶段、开发阶段、运行阶段、消亡阶段**。讲义 p7 图示：开发阶段以曲线箭头指向"单个系统开发"框（总体规划→系统分析→系统设计→系统实施→系统验收）。

### 1. 产生阶段

也叫**概念阶段**或**需求分析阶段**，分两个过程：

- **概念的产生过程**：根据企业经营管理的需要，提出建设信息系统的初步想法
- **需求分析过程**：对企业信息系统的需求进行深入调研和分析，形成需求分析报告

### 2. 开发阶段（最重要、最关键，五个子阶段顺序必背）

| # | 子阶段 | 要点 |
|---|---|---|
| 1 | **总体规划** | 系统开发的**起始阶段**，基础是**需求分析**；作用：指明信息系统在企业经营战略中的作用和地位、指导开发、优化配置和利用资源；内容包括开发目标、总体架构、组织结构和管理流程、实施计划、技术规范 |
| 2 | **系统分析** | 目标是为系统设计提供系统的**逻辑模型**；以企业业务流程分析为基础，是管理流程和信息流程的交汇点；内容：组织结构及功能分析、业务流程分析、数据和数据流程分析、系统初步方案 |
| 3 | **系统设计** | 根据系统分析结果设计**实施方案**；内容：系统架构设计、数据库设计、处理流程设计、功能模块设计、安全控制方案设计、系统组织和队伍设计、系统管理流程设计 |
| 4 | **系统实施** | 将设计在计算机和网络上具体实现（设计文本→可运行软件）；是对以前全部工作的检验，**用户的参与特别重要**；此后用户逐步变为系统的主导地位 |
| 5 | **系统验收** | 实施结束后进入**试运行**，性能优劣与是否用户友好暴露出来，即进入验收 |

### 3. 运行阶段

通过验收、**正式移交给用户**以后进入运行阶段。长时间的运行是检验系统质量的试金石；保障正常运行不可缺少的工作是**系统维护**。

**维护四类型（必背）**：**排错性维护、适应性维护、完善性维护、预防性维护**。一般系统运行**初期排错性/适应性维护比较多**，**后期完善性/预防性维护比较多**。

### 4. 消亡阶段

系统不可避免地会遇到**系统更新改造、功能扩展，甚至报废重建**。在信息系统建设**初期**就应当注意系统的消亡条件和时机，以及由此而花费的成本。

> [!warning] 易错点
> ①开发五子阶段常考排序调换：**总体规划在最前、系统验收在最后**；②"系统分析产出**逻辑模型**、系统设计产出**实施方案**"一一对应不可混；③产生阶段别名为"概念阶段/需求分析阶段"，**不是**"可行性研究阶段"；④"消亡阶段"最易被忽视（官方原文：几乎完全被忽视），建设初期就要考虑消亡条件与成本。

> [!tip] 来源：官方教程 §3.1.4 物理p129-131（四阶段定义/五子阶段/维护四类型/消亡），讲义 p7 生命周期图为骨架。

## 二、诺兰阶段模型（六阶段）

官方 §3.1.2：**1979 年**，美国管理信息系统专家**诺兰（Richard L. Nolan）**通过对 **200 多个公司、部门**发展信息系统的实践和经验总结，提出信息系统进化的阶段模型（诺兰模型）：任何组织由手工信息系统向以计算机为基础的信息系统发展时，都存在着一条客观的发展道路和规律。

| # | 阶段 | 主要特点 |
|---|---|---|
| 1 | **初始阶段** | 计算机只作为办公设备（报表统计，甚至当打字机用）；①组织中**只有个别人**具有使用计算机的能力；②一般发生在组织的**财务部门** |
| 2 | **传播阶段** | 数据处理能力**迅速发展**、投入大幅增加、热情高涨；出现许多新问题（**数据冗余、数据不一致性、难以共享**、计算机使用效率不高） |
| 3 | **控制阶段** | 从整体上控制计算机信息系统的发展；①**成立了一个领导小组**；②**采用了数据库（DB）技术**；③是**计算机管理变为数据管理的关键**；职能部门内部网络化，但存在"**部门壁垒**"与"**信息孤岛**" |
| 4 | **集成阶段** | 在控制基础上重新规划设计，建立基础数据库与统一信息管理系统；①**建立集中式的 DB 及相应的 IS**；②增加大量硬件，**预算费用迅速增长** |
| 5 | **数据管理阶段** | 选定统一的数据库平台、数据管理体系和信息管理平台，统一数据的管理和使用，各部门基本实现**资源整合和信息共享** |
| 6 | **成熟阶段** | 信息系统满足企业各个层次的需求，真正把 **IT 与管理过程结合起来**，提升竞争力和发展潜力 |

> [!warning] 时代划分（原文必背）
> **前 3 个阶段具有计算机时代的特征，后 3 个阶段具有信息时代的特征，其转折点是进行信息资源规划的时机。**

> [!tip] 来源：官方教程 §3.1.2 物理p121-122。

## 三、信息系统建设原则

官方 §3.1.5：信息系统规划设计及开发过程中必须遵守的原则，是系统成功的必要条件。

| 原则 | 要点 |
|---|---|
| 1. **高层管理人员介入原则** | 信息系统建设目标总是为企业总体目标服务；真正理解企业总体目标的是高层管理人员；"介入"可以是直接参加、决策或指导，也可以是政治/经济/人事等方面的支持；现阶段具体化为 **CIO（首席信息官）**——相当于副总裁的高级职位，主持制定公司信息规划、政策、标准 |
| 2. **用户参与开发原则** | "用户第一/用户至上"；核心用户是**信息系统的使用者**（单位领导只是辅助/外围用户）；核心用户应**参与全过程的开发**（从概念规划设计直到系统运行）；用户应深度参与——既以甲方代表身份出现，又应成为真正的系统开发人员 |
| 3. **自顶向下规划原则** | 主要目标是**达到信息的一致性**（信息不一致对信息系统往往是致命的，甚至造成报废）；但自顶向下规划**绝不能取代信息系统的详细设计** |
| 4. **工程化原则** | 源于"软件危机"教训（软件可靠性问题，根本原因是没有工程化）→ 发展出软件工程；信息工程、系统工程等工程化方法引入信息系统开发 |
| 5. 其他原则 | **创新性原则**（体现**先进性**）、**整体性原则**（体现**完整性**）、**发展性原则**（体现**超前性**）、**经济性原则**（体现**实用性**） |

> [!tip] 来源：官方教程 §3.1.5 物理p125-126。

## 四、信息系统开发方法（核心考点）

### 1. 四种开发方法对比（讲义 p9 + 官方 §3.1.6）

| 方法 | 基本思想 | 适用场景 | 优点 | 缺点/局限 |
|---|---|---|---|---|
| **结构化方法** | **自顶向下**、逐步分解求精；将生命周期划分为系统调查、系统分析、系统设计、系统实施、系统维护等阶段，在**结构化和模块化**基础上开发 | 业务比较**成熟、定型**的系统，如**银行、电信、商品零售**等行业 | 四大特点：①**开发目标清晰化**（遵循"用户第一"，保持与用户沟通）；②**工作阶段程式化**（每阶段内容明确、完成后审查，避免留隐患）；③**开发文档规范化**（保证阶段衔接与维护便利）；④**设计方法结构化**（子系统相对独立，便于分析、设计、实现与维护） | **应变能力差**（讲义 p9） |
| **原型法** | 根据用户需求利用开发工具**快速建立一个系统模型**展示给用户，在此基础上与用户交流，**多次反复**直到用户满意；过程：系统需求分析→系统初步设计→系统调试→系统检测 | **需求不明确**的系统（讲义 p9 标注"针对需求不明确"、作用在**需求阶段**） | 快速建模、用户全程试用评价、不断细化扩充直到满意 | 讲义/官方未明列缺点（考试不考，以讲义为准） |
| **面向对象方法** | **自底向上**；把客观世界看成由相互配合、协作的对象组成的系统；利用实体、关系、属性等建模概念，运用**封装、继承、多态**机制构造模拟现实系统；初始元素是**对象**→归纳成**类**→组织类的等级关系→**构造类库** | 需要复用与应变能力的系统 | **更好应变、更好复用、符合人们的思维习惯**（讲义 p9）；集成了以前各种方法的优点，避免了各自的缺点 | **阶段界限不明**（讲义 p9） |
| **面向服务的方法** | 将相关对象按业务功能分组→**构件**概念；跨构件功能调用以**接口**暴露；**接口定义与实现解耦**→催生服务和面向服务的开发方法 | 需要**快速响应需求与环境变化**、提高**可复用性、信息资源共享和系统间互操作性**的系统 | **粗粒度、松耦合、标准化和构件化**（讲义 p9）；代表不拘泥于具体技术实现方式的新开发思想，已成为信息系统建设的大趋势 | 较新的领域，许多研究和实践还有待进一步深入 |

**面向服务的抽象级别**（讲义 p9）：**操作【低】→ 服务【中】→ 业务流程【高】**。

### 2. 原型法的分类（高频）

- **按功能分**：**水平原型**（界面）、**垂直原型**（复杂算法）
- **按最终结果分**：**抛弃式原型**、**演化式原型**

### 3. 其他开发方法（讲义 p10）

| 方法 | 要点 |
|---|---|
| **形式化方法** | 建立在**严格数学基础**上的软件开发方法（讲义 p11 真题定义）；代表：**净室软件工程**——在**受控污染级别的环境**中开发，**数学模型化**，所有东西均**可证明/验证，而不是测试** |
| 统一过程方法（UP） | 讲义仅列条目 |
| 敏捷方法 | 讲义仅列条目 |
| 基于架构的开发方法（ABSD） | 讲义仅列条目 |

> [!warning] 易错点
> ①**自顶向下 = 结构化方法**，**自底向上 = 面向对象方法**，定义判断常互换出题；②原型法对应"需求不明确/需求阶段"，结构化法对应"业务成熟定型"，张冠李戴是常见干扰；③净室 = 证明/验证**而不是测试**；④"阶段界限不明"是面向对象方法的局限，不是优点。

> [!tip] 来源：讲义 p9-10 为骨架（对比条目/原型分类/其他方法），官方教程 §3.1.6 物理p126-127 补肉（四方法详细表述/适用行业/构件-接口-服务演化链）。

## 五、业务处理系统 TPS（概念）

官方 §3.2：

- **TPS（Transaction Processing System）** 又称**电子数据处理系统（EDP）**，是计算机在管理方面**早期应用的最初级形式**的信息系统；服务于组织管理层次中**最低层、最基础**（作业层），通常是分离式单独处理某一项具体事务的系统（账务处理、工资管理、物料进出库、合同管理等）
- 主要目的：帮助作业层管理人员**减轻处理原始数据的负担**、提高具体事务处理效率；处于企业系统边界的 TPS 将企业和外部环境联系起来（"桥梁"）
- **TPS 是其他类型信息系统的信息产生器**；企业推进全面信息化往往**从开发 TPS 入手**；TPS 一旦故障可能导致企业运作紊乱（航空订票、银行存取款系统）
- **数据处理周期五阶段**：**数据输入、数据处理、数据库的维护、文件报表的生成、查询处理**
- 数据处理两种方式：**批处理**（积累一段时间定期处理，如银行每日账目；优点是经济，缺点是间隔期主文件易过时、无法满足实时查询）与**联机事务处理 OLTP/实时处理**（立即处理、立即更新、即时响应查询；依赖网络；容错技术：**双 CPU、后备机、保存冗余数据**；缺点是成本高、需授权机制）
- TPS 面对**结构化程度很高**的管理问题 → 可采用**结构化生命周期法**开发；且已日益商品化，可直接购买后二次开发

> [!tip] 来源：官方教程 §3.2 物理p127-133。信息系统的五类分类（TPS/MIS/DSS/ES/OAS 细节）归 0503 节，此处只记 TPS 基础概念。

> [!tip] 记忆口诀
> - 生命周期四阶段："**产开运亡**"；开发五子阶段："**总析设实收**"（总体规划→系统分析→系统设计→系统实施→系统验收）
> - 维护四类型："**错适完预**"——初期错、适多，后期完、预多
> - 诺兰六阶段："**初传控集，数管成熟**"；**初始财务、控制用 DB、集成集中 DB 且烧钱**；前 3 计算机、后 3 信息，转折 = 信息资源规划
> - 四方法：**结构化"顶、清程规构、成熟定型（银行电信零售）、应变差"**；**原型"需求不明、快速建模、多次反复、水平界面垂直算法、抛弃演化"**；**面向对象"底、复用应变合思维、阶段界限不明"**；**面向服务"粗粒度松耦合、操作-服务-业务流程"**
> - 其他方法：形式化 = "**数学基础、可证明验证非测试、净室受控污染**"
> - TPS："**最低层最基础、信息产生器、五阶段输入处理库维护报表查询、批处理 vs OLTP、适合结构化法**"
