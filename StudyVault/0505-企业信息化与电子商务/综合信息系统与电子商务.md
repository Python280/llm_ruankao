# 综合信息系统与电子商务

> 本节覆盖讲义 p34-53：ERP/CRM/SCM/BI 四大企业信息系统、数据仓库与数据湖、BPR/BPM、企业应用集成（EAI）、企业门户、电子商务类型。配套练习见 [[练习题-企业信息化与电子商务]]；信息化概念与战略规划见 [[企业信息化与战略规划]]。

## 企业信息化架构总览

企业信息化工程**核心技术四项**：**信息技术、自动化技术、现代管理技术、制造技术**。

架构三层（讲义 p34 图）：

- 上层（业务块）：制造及分销、财务、人力资源、呼叫中心、销售管理、市场分析、供应链/物流/结算管理、公文流转、协同工作、知识共享
- 中层（系统）：**PDM 产品数据管理系统、车间控制系统、ERP、CRM、SCM、OA/KM 办公自动化知识管理系统**
- 下层（总线）：**企业信息总线（Enterprise Information Bus）**，内含**数据仓库 DW** 和**数据挖掘、在线分析和决策支持系统 DM/OLAP/DSS**

另有**企业信息门户（Enterprise Information Portal）**作为统一入口。

## ERP 企业资源计划

### 演进路线（MRP → MRPII → ERP）

| 阶段 | 全称 | 题眼 |
|---|---|---|
| MRP | 物料需求计划 Material Requirement Planning | 物料/零部件需求 |
| MRPII | 制造资源计划 Manufacturing Resource Planning II | **核心是物流，主线是计划** |
| ERP | 企业资源计划 Enterprise Resource Planning | **打通了供应链**；**扩展到了非制造业**；**重心转移到财务上** |

由美国 **Gartner Group 公司 1990 年**提出。ERP 是建立在信息技术基础上，利用现代企业的先进管理思想，全面集成企业所有资源信息，并为企业提供**决策、计划、控制与经营业绩评估**的全方位和系统化的管理平台。

### 结构原理（官方 §3.7，大纲考点）

企业的**三大流资源**：**物流、资金流、信息流**。ERP 就是对这"三流"进行全面集成管理的管理信息系统。MRPII 核心是物流、主线是计划，但 **ERP 已将管理重心转移到财务上**，在整个经营运作过程中贯穿**财务成本控制**的概念。

**ERP 结构原理图的 11 个基本模块**（图 3-16）：生产预测、销售管理、经营计划（生产计划大纲）、主生产计划、物料需求计划、能力需求计划、车间作业计划、采购与库存管理、质量与设备管理、财务管理、有关扩展应用模块。

**五层次计划体系**（从决策层到执行层）：

| 计划 | 要点（官方原文压缩） |
|---|---|
| 生产预测 | 前 3 层次计划（经营计划、生产计划大纲、主生产计划）都离不开预测；方法：**德尔菲法、移动平移法、指数平滑法、非线性最小二乘曲线拟合法** |
| 销售管理 | 从计划角度属于**最高层计划**范畴，最重要的决策层计划之一 |
| 经营计划（生产计划大纲 PP） | 经营计划的细化，描述可用资源条件下的产量计划；**承上启下** |
| 主生产计划 MPS | 说明一定时期内**生产什么、生产多少、什么时候交货**；是物料需求计划的编制依据；编制是 ERP 的主要工作内容 |
| 物料需求计划 MRP | 对 MPS 各项目所需全部制造件/采购件的**网络支持计划和时间进度计划**；**生产管理的核心**；属 **ERP 管理层计划** |
| 能力需求计划 CRP | 核算 MRP 所需能力，比较需求与现有生产能力，**及早发现能力瓶颈** |
| 车间作业计划 PAC | 在 MRP 自制件计划基础上按交货期、优先级、车间资源下达订单；属 **ERP 执行层计划**；主流模式是 **JIT（Just In Time）** |

其他模块：**采购与库存管理**（采购订单产生至货物收到全过程；物料进、出、存）；**质量与设备管理**（全面质量管理 **TQM**，全过程、全员责任）；**财务管理**（综合性管理，渗透在全面经济活动中）；**扩展应用模块**（客户关系管理、分销资源管理、供应链管理、电子商务——本身也是独立系统/独立软件产品）。

### ERP 三大功能（官方 §3.7.3）

1. **支持决策的功能**：把制造、营销、财务系统紧密结合，实现全球多工厂、多地点跨国经营；对质量控制、市场变化、客户满意度、经营效绩提供**实时分析**
2. **为不同行业提供有针对性的 IT 解决方案**：打破 MRPII 只局限传统制造业的格局，扩展到商业零售、金融、能源、公共事业、工程建筑等行业
3. **从企业内部供应链发展为全行业和跨行业的供应链**：管理范围拓展到整个行业的原材料供应、生产加工、配送、流通及最终消费者，多企业在整体 ERP 管理下**协作经营和协调运作**

## CRM / SCM / BI / ERP 速对比

| 系统 | 一句话定位 | 核心思想/目的 |
|---|---|---|
| **ERP** | 企业内部资源全面集成管理 | 对物流、资金流、信息流"三流"全面集成；重心在**财务** |
| **CRM** | 客户关系管理 Customer Relationship Management | 目的是**提高收入**；核心思想是**以客户为中心** |
| **SCM** | 供应链管理 Supply Chain Management | 强强联合，整合与优化"**三流**"，打通企业间信息孤岛，严格的数据交换标准 |
| **BI** | 商业智能 Business Intelligence | **决策分析**：分析历史数据预判未来 |

**CRM 四主要模块**：销售自动化、营销自动化、客户服务与支持、商业智能。**CRM 三价值**：提高工作效率、节省开支；提高客户满意度；提高客户忠诚度。

**SCM 的三流**（★讲义标星）：

| 流 | 地位 | 说明 |
|---|---|---|
| **信息流** | **核心** | 需求信息流（需方→供方）：客户订单、生产计划、采购合同等；供应信息流（供方→需方）：入库单、完工报告单、库存记录、可供销售量、提货发运单等 |
| 资金流 | 辅助 | |
| 物流 | 辅助 | |

SCM 环链角色：**供应商 → 制造商 → 分销商 → 零售商**；中心环节：**计划（策略性）、采购、制造、配送、退货**。

## 商业智能（BI）、数据仓库与数据挖掘

**BI 与普通应用系统对比**（讲义 p38 图）：

| | 商业智能（BI） | 普通应用系统 |
|---|---|---|
| 用途 | **决策分析**（分析历史数据预判未来） | **支撑业务运作** |
| 组成 | **数据仓库 + OLAP（联机分析处理）+ 数据挖掘** | 应用数据库 + OLTP（联机事务处理） |

**数据仓库四大特点**（与数据库对比，选择题高频）：

| 数据库 | 数据仓库 |
|---|---|
| **面向应用**：按应用组织数据 | **面向主题**：按主题组织数据 |
| **零散的**：一个应用对应一个数据库 | **集成的**：整个企业对应一个数据仓库 |
| **CRUD**：增删改查是常态 | **相对稳定的（非易失的）**：查询为主、基本无修改与删除 |
| 解决**当下**应用问题 | **反映历史变化（时变的）**：各阶段信息都有，并可预测未来趋势 |

**数据仓库架构**：数据源 →（**抽取、清理、装载、刷新**）→ 数据仓库 → 数据集市；向上经 **OLAP 服务器**提供查询报表与数据分析。OLAP 支持**上卷、下钻和旋转**分析（三维分析立方体：产品 × 城市 × 月份）。

**数据挖掘四类**（利用隐藏的知识做分析与预测）：

| 类型 | 题眼 |
|---|---|
| **关联分析** | 挖掘出隐藏在数据间的**相互关系** |
| **序列模式分析** | 侧重分析数据间的**前后关系（因果关系）** |
| **分类分析** | 为每一条记录**赋予一个标记**再按标记分类 |
| **聚类分析** | **分类分析法的逆过程**（自动聚成若干组） |

> [!tip] 来源
> 讲义 p38-41；p42-43 习题见 [[练习题-企业信息化与电子商务]] Q4。

## 数据湖 vs 数据仓库

- **数据湖**：存储企业**各种各样原始数据**的大型仓库，数据可供存取、处理、分析及传输；既含**结构化数据**也含**非结构化数据**（图片、视频、音频、文档）
- **数据仓库仅支持数据分析处理**；**数据湖既支持数据分析处理，也支持事务处理**

| 维度 | 数据仓库 | 数据湖 |
|---|---|---|
| 数据 | **清洗过的、结构化的**数据 | **原始数据**；结构化、半结构化 |
| 模式 | 存储**之前**定义模式；集成前完成大量工作；价值**提前明确** | 存储**之后**定义模式；敏捷简单的集成；价值**尚未明确** |
| 存取方法 | **标准 SQL** 接口 | 应用程序、类 SQL 的程序 |
| 优势 | 多数据源集成；干净安全；转换一次多次使用 | 无限扩展性；并行执行；支持编程框架；数据经济 |

> [!tip] 来源
> 讲义 p44-45。

## 企业应用集成（EAI）

**背景**：系统未互联互通，存在**信息孤岛**，这种架构也被称为**烟囱架构**；EAI 用于**消除信息孤岛**，使系统互联互通。

**四个层次**（业界无统一划分标准，讲义列四种）：

| 层次 | 别名 | 集成点 | 效果/题眼 |
|---|---|---|---|
| **表示集成** | 界面集成 | **界面** | 统一入口，产生"**整体**"感觉；**最小代价**实现一体化操作 |
| **数据集成** | — | **数据**（中间件如 JDBC） | 不同来源的数据逻辑或物理上"**集中**" |
| **控制集成** | 应用集成、API 集成 | **应用逻辑**（API = Application Programming Interface） | 在应用逻辑层互通 |
| **业务流程集成** | 过程集成、B2B | 流程 | 跨企业业务流程打通 |

集成**难度自上而下递增**（表示集成最易 → 业务流程集成最难）。

**三种集成方式选择**（讲义 p52，按数据量与交互频度选型）：

| 方式 | 特点 |
|---|---|
| **消息集成** | 数据量**小**，交互**频繁**，立即地，**异步** |
| **共享数据库** | 交互频繁，立即地，**同步** |
| **文件传输** | 数据量**大**，交互频度**低**，即时性要求低（月末、年末） |

> [!tip] 来源
> 讲义 p47-49、p52。

## 企业门户四类

| 门户 | 全称 | 题眼 |
|---|---|---|
| **EIP** | 企业信息门户 Enterprise Information Portal | 员工/合作伙伴/客户/供应商访问企业内外部所需信息的**统一访问入口** |
| **EKP** | 企业知识门户 Enterprise Knowledge Portal | 企业网站基础上增加知识性内容，**企业知识库** |
| **EAP** | 企业应用门户 Enterprise Application Portal | 以**商业流程和企业应用为核心**，把功能不同的应用模块通过门户技术集成在一起，**企业信息系统的网上集成界面** |
| **垂直门户** | — | 为**某一特定行业**服务，传送的信息只属于人们感兴趣的领域 |

## 电子商务

电子商务主要有 **2 类角色**：企业（**B**usiness）及个人（**C**ustomer）。

| 类型 | 含义 | 典型应用（讲义举例） |
|---|---|---|
| **B2B** | 企业对企业 | **1688** |
| **C2C** | 个人对个人 | **闲鱼** |
| **B2C** | 企业对个人 | **京东、天猫** |
| **C2B** | 个人对企业 | 个人给企业提供咨询服务 |
| **O2O** | Online To Offline，线上对线下 | **团购** |
