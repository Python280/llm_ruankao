# 系统工程方法与生命周期

## 系统工程概念（四定义 + 整体最优）

讲义对"系统工程"给出四条核心表述，做题时四条都算正确说法：

| # | 定义角度 | 原文要点 |
|---|---|---|
| 1 | 性质 | 系统工程是一种**组织管理技术** |
| 2 | 科学方法 | 为了最好地实现系统的目的，对系统的**组成要素、组织结构、信息流、控制机构**进行分析研究的科学方法 |
| 3 | 出发点 | **从整体出发、从系统观念出发**，以求**整体最优** |
| 4 | 工具与目的 | **利用计算机作为工具**，对系统的**结构、元素、信息和反馈**等进行分析，以达到**最优规划、最优设计、最优管理、最优控制** |

另有：**系统工程方法**是一种**现代的科学决策方法**，其特点是**整体性、综合性、协调性、科学性和实践性**。

官方教程补充的权威定义（判断题爱换措辞）：

- **钱学森（1978）**："系统工程"是组织管理"系统"的**规划、研究、设计、制造、试验和使用**的科学方法，是一种对所有"系统"都具有普遍意义的科学方法
- **INCOSE（国际系统工程学会）**：系统工程（SE）是一种使系统能够成功实现的**跨学科的方法和手段**；在开发周期早期就定义客户需求与所要求的功能，再考虑完整问题（运行、成本、进度、性能、培训、保障、实验、制造和退出），进行设计综合和系统确认
- 定义中的关键词：**跨学科、技术和整体性**；系统工程的核心集中在**分析和设计与其部分截然不同的整体**
- 另记：系统工程产生于**第二次世界大战期间**，**1960 年美国阿波罗登月计划**成功运用系统工程方法

## 五大系统工程方法（总览）

| 方法 | 一句话题眼 |
|---|---|
| 霍尔三维结构 | **"硬科学"方法论**；时间维/逻辑维/知识维；组织管理大型工程 |
| 切克兰德方法 | **"软科学"方法论**；核心是"比较"与"探寻"而非"最优化" |
| 并行工程 | "制造过程"与"支持过程"**并行、集成化**处理 |
| 综合集成法 | 钱学森命名；**简单系统**与**巨系统**；从定性到定量 |
| WSR 系统方法 | 实践准则：**懂物理、明事理、通人理** |

## 霍尔三维结构（硬系统方法论）

美国系统工程专家**霍尔（A.D.Hall）等人 1969 年**提出；后人将其与软系统方法论对比，称为**硬系统方法论（HSM）**。集中体现系统工程方法的**系统化、综合化、最优化、程序化和标准化**等特点。应用场景：**组织和管理大型工程建设项目**（寻求"战术"问题最优策略）。

三维 = **时间维（工作进程）+ 逻辑维（解决问题的逻辑过程）+ 知识维（专业科学知识）**。

**时间维 7 阶段**（按时间顺序排列的全过程）：

| 阶段 | 工作内容（题眼） |
|---|---|
| 1 规划阶段 | 调研、程序设计阶段，谋求活动的规划与战略 |
| 2 拟订方案 | 提出具体的计划方案 |
| 3 研制阶段 | **作出研制方案及生产计划** |
| 4 生产阶段 | 生产系统的零部件及整个系统，提出安装计划 |
| 5 安装阶段 | 安装完毕，完成系统的运行计划 |
| 6 运行阶段 | 系统按照预期的用途开展服务 |
| 7 更新阶段 | 改进原有系统或取消旧系统代之以新系统 |

**逻辑维 7 步骤**（时间维每个阶段内的思维程序）：

1. 明确问题 → 2. 确定目标（建立价值体系或评价体系）→ 3. 系统综合 → 4. 系统分析 → 5. 优化（系统方案的优化选择）→ 6. 决策（讲义作"系统决策"）→ 7. 实施（讲义作"实施计划"）

**知识维**：工程、医学、建筑、商业、法律、管理、社会科学、艺术等各种知识和技能。

## 切克兰德方法（软科学方法论·比较学习）

20 世纪 70 年代起系统工程对象"软化"（社会经济发展战略、组织管理问题，因素难以量化），80 年代中前期英国 **P.切克兰德（P.Checkland）** 提出代表性**软系统方法论**。

- 切克兰德把霍尔方法论称为"硬科学"方法论；认为完全按工程思路解决社会/"软科学"问题，在**设计价值系统、模型化和最优化**等步骤会碰到许多难以定量分析的困难
- **核心不是"最优化"而是"比较"与"探寻"**：从**模型和现状的比较**中来**学习**改善现状的途径；"比较"含有组织讨论、听取各方面有关人员意见的意思，不拘泥于定量分析
- 适用于**社会经济系统**这类事先难以确定清楚需求的问题

**7 个步骤**（顺序是考点）：

1. **认识问题**（收集信息、表达现状、确定行为主体和利益主体）
2. **根底定义**（弄清关键要素及关联因素，确立基本看法）
3. **建立概念模型**（不能建精确数学模型时，用结构模型或语言模型描述现状；来自根底定义）
4. **比较及探寻**（现实问题与概念模型对比，找出可行方案或途径）
5. **选择**（考虑人员态度及社会、行为因素，选出可行的改善方案）
6. **设计与实施**
7. **评估与反馈**（修正问题描述、根底定义及概念模型）

> [!tip] 来源
> 讲义 p4；官方教程 §2.8.2；32h 印刷 p43。

## 并行工程方法

**并行工程（Concurrent Engineering）**：对产品及其相关过程（包括**制造过程和支持过程**）进行**并行、集成化处理**的系统方法和综合技术。

- 要求产品开发人员**从设计开始就考虑产品生命周期的全过程**：不仅考虑质量、成本和用户要求等各项性能，还考虑相关工艺过程的质量及服务的质量
- **目标：提高质量、降低成本、缩短产品开发周期和产品上市时间**
- 做法：开发初期组织多种职能协同工作的项目组，使问题在开发早期解决，避免返工浪费

**强调 3 点**：

1. 设计开发期间，将**概念设计、结构设计、工艺设计、最终需求**结合起来，以最快速度按要求质量完成
2. 各项工作由相关的**项目小组**完成，随时或定期反馈信息、协调解决问题
3. 依据适当的**信息系统工具**反馈与协调整个项目；利用现代 **CIM 技术**辅助并行化

> [!tip] 来源
> 讲义 p4；官方教程 §2.8.2；32h 印刷 p43。

## 综合集成法（钱学森·开放的复杂巨系统）

**1990 年初，钱学森等**首次把处理开放的复杂巨系统的方法命名为**从定性到定量的综合集成法**。综合集成是**从整体上**考虑并解决问题的方法论（不同于培根式的还原论方法）。

**系统分类**（按子系统种类多少与关联复杂程度）：

- **简单系统**：子系统数量少、关系单纯（如一台测量仪器）
- **巨系统**：子系统数量非常巨大（成千上万）
  - **简单巨系统**：种类不太多且关联简单（如激光系统）
  - **复杂巨系统**：种类很多并有层次结构、关联复杂；若又开放 → **开放的复杂巨系统**

**开放的复杂巨系统**：

- **四原则**：①整体论原则 ②相互联系的原则 ③有序性原则 ④动态原则
- **五性质**：①开放性 ②复杂性 ③进化与涌现性 ④层次性 ⑤巨量性

1992 年钱学森进一步提出建设**从定性到定量的综合集成研讨厅体系**的设想（专家群体 + 数据信息 + 计算机/网络信息技术三者结合，基于网络）。

**综合集成方法五特点**：①定性研究与定量研究有机结合、贯穿全过程；②科学理论与经验知识结合；③应用系统思想把多种学科结合起来综合研究；④宏观研究与微观研究统一；⑤必须有大型计算机系统支持（含 MIS、DSS 及综合集成功能）。

> [!tip] 来源
> 讲义 p4；官方教程 §2.8.2；32h 印刷 p43。

## WSR 系统方法（物理-事理-人理）

**WSR = 物理（Wuli）-事理（Shili）-人理（Renli）** 方法论的简称，**顾基发教授和朱志昌博士 1994 年在英国 HULL 大学**提出。

- 既是方法论又是解决复杂问题的工具；具有**中国传统哲学的思辨思想**，是多种方法的综合统一；属于**定性与定量分析综合集成的东方系统思想**
- **实践准则："懂物理、明事理、通人理"**（形容人"通情达理"即成功实践了 WSR）

**一般工作过程 7 步**：理解意图 → 制定目标 → 调查分析 → 构造策略 → 选择方案 → 协调关系 → 实现构想。步骤不一定严格依序，**协调关系始终贯穿整个过程**（协调人与人、物理/事理/人理、意图与目标、投入产出等关系）。

三理对应的方法：

| 理 | 主要方法 |
|---|---|
| 物理 | 自然科学中的各种科学方法 |
| 事理 | 运筹学、系统工程、管理科学、控制论、数学方法、软计算（进化/模糊/网络计算）、特尔斐法、层次分析法等 |
| 人理 | 关系、感情、习惯、知识、利益、斗争、和解、和谐、管理 |

> [!tip] 来源
> 讲义 p4；官方教程 §2.8.2；32h 印刷 p43。

## MBSE 三支柱

**2007 年 INCOSE《系统工程 2020 年愿景》**正式提出 **MBSE（基于模型的系统工程，Model-Based Systems Engineering）** 定义：MBSE 是**建模方法的形式化应用**，以使建模方法支持系统**需求、分析、设计、验证和确认**等活动，从概念性设计阶段开始，持续贯穿到设计开发以及后来的所有生命周期阶段。

MBSE 仍然是系统工程（层层分解、综合集成的思路不变），核心是采用**形式化、图形化、关联化**的建模语言及工具改造系统工程技术过程。

**三大支柱：建模语言、建模工具、建模思路**。

| 支柱 | 要点 |
|---|---|
| 建模语言 | **SysML**（Systems Modeling Language）：OMG 在对 **UML 2.0 的子集**重用和扩展的基础上提出，作为系统工程的标准建模语言；优点：通用语言、图形化可视化、便于计算机处理 |
| 建模工具 | 支持系统建模语言画图的计算机和网络环境，核心是支持建模语言的软件；可构建分布式建模环境协同设计 |
| 建模思路 | 设计团队如何利用各种图形建立系统模型（即工作流程），如 Harmony-SE、SYSMOD、OOSEM；**应是重点工作和前置性工作** |

**系统工程过程三阶段产生的三种图**（高频考点）：

| 阶段 | 产生的图 |
|---|---|
| 需求分析阶段 | 需求图、用例图、包图 |
| 功能分析与分配阶段 | 顺序图、活动图、状态机（State Machine）图 |
| 设计综合阶段 | 模块定义图、内部块图、参数图 |

> [!tip] 来源
> 官方教程 §2.8.4（物理 p118-119）；32h 印刷 p43-44。讲义 p3-8 未单列 MBSE 页，此节以官方 + 32h 为准。

## 生命周期：系统工程七阶段 vs 信息系统四阶段

**系统工程生命周期七阶段**（按 ISO/IEC 15288:2008）：

**探索性研究 → 概念阶段 → 开发阶段 → 生产阶段 → 使用阶段 → 保障阶段 → 退役阶段**

| 阶段 | 目的（官方原文压缩） |
|---|---|
| 探索性研究 | 识别利益攸关者需求，探索创意和技术 |
| 概念阶段 | 细化需求，探索可行概念，提出有望实现的解决方案 |
| 开发阶段 | 细化系统需求，创建解决方案描述，构建系统，验证并确认（V&V） |
| 生产阶段 | 生产系统并进行检验和验证 |
| 使用阶段 | 运行系统以满足用户需求 |
| 保障阶段 | 提供持续的系统能力（维护流程） |
| 退役阶段 | 存储、归档或退出系统（退出计划在概念阶段即定义） |

定义系统生命周期的目的：以**有序而且高效的方式**建立一个**满足利益攸关者需求**的框架。跳过阶段、省去决策会大幅增加风险。

**四种生命周期方法**：

| 方法 | 题眼 |
|---|---|
| 计划驱动方法 | 需求→设计→构建→测试→部署；关注文档完整性、需求可追溯性、事后验证 |
| 渐进迭代式开发（IID） | 提供初始能力后**连续交付**以达到期望系统；适用于需求不清晰或较小的系统 |
| 精益开发 | 起源于**丰田"准时化"**哲学；动态的、知识驱动的、以客户为中心；消除浪费 |
| 敏捷开发 | 关键目标在于**灵活性**；欢迎需求变更、不断交付可用软件、面对面交谈 |

**信息系统生命周期四阶段**（讲义 p7）：

**产生阶段 → 开发阶段 → 运行阶段 → 消亡阶段**

- **产生阶段**：提出建设信息的初步想法、对需求进行调研和分析
- **开发阶段**：单个系统开发五步 = **总体规划 → 系统分析 → 系统设计 → 系统实施 → 系统验收**
- **运行阶段**：通过验收、移交之后
- **消亡阶段**：更新改造、功能扩展、报废重建

> [!tip] 来源
> 讲义 p6-7；官方教程 §2.8.3（物理 p112-114）；32h 印刷 p43。

> [!warning] 两套"生命周期"勿混
> ①**系统工程**生命周期 = **7 阶段**（探索性研究…退役）；②**信息系统**生命周期 = **4 阶段**（产生/开发/运行/消亡），其中开发阶段内含五步。题干问哪套就答哪套的阶段名。
