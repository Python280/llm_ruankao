# 内核架构与鸿蒙

## 内核概念

- 内核是操作系统的**核心部分**，管理着系统的各种资源
- 内核可看成**连接应用程序和硬件的一座桥梁**
- 是**直接运行在硬件上的最基础的软件实体**

按内核架构划分：**宏内核（Monolithic Kernel）**和**微内核（Micro Kernel）**。

## 宏内核 vs 微内核结构对比（p33 结构图）

| | 宏内核 | 微内核 |
|---|---|---|
| 用户空间 | 多个应用程序进程，经系统 API 进入内核 | 应用程序进程 + **各服务进程**（内存管理、进程管理、文件管理、设备管理服务进程）+ **各驱动程序服务进程** |
| 内核空间 | 进程管理、内存管理、设备管理、文件管理功能代码及驱动程序**及其他功能代码（全部在内核）** | **仅 4 类代码**：进程调度器、内存空间映射、中断处理、**进程间通信** |

## 宏内核 vs 微内核对齐表

| | 实质 | 优点 | 缺点 |
|---|---|---|---|
| 单体内核（宏内核） | 将**图形、设备驱动及文件系统**等功能**全部在内核中实现**，运行在**内核状态和同一地址空间** | 减少进程间通信和状态切换的系统开销，获得**较高的运行效率** | 内核庞大，**占用资源较多且不易剪裁**；系统的**稳定性和安全性不好** |
| 微内核【**鸿蒙操作系统**】 | **只实现基本功能**，将图形系统、文件系统、设备驱动及通信功能**放在内核之外** | ①结构相当**清晰**，有利于**协作开发**；②内核精练，便于**剪裁和移植**（灵活性、可扩展性）；③服务程序运行在**用户地址空间**，**可靠性、稳定性、安全性较高**；④可用于**分布式系统** | 用户状态和内核状态需要**频繁切换**，导致系统**效率不如单体内核，性能偏低** |

> [!tip] 记忆口诀
> - 宏内核："**全塞内核里，快但脆**"（效率高 / 庞大难剪裁 / 稳定性安全性差）
> - 微内核："**内核只留调度 + IPC，其余变用户态服务，稳但慢**"
> - 考试绑定：**鸿蒙 = 微内核**

## 微内核 C/S 结构

微内核系统采用**客户/服务器（C/S）结构**：

- **用户态**：客户进程 + 各类**服务器**（进程服务器、终端服务器、文件服务器、存储器服务器……）
- **核心态**：只有**核心**（微内核本体）

交互流程：**客户进程向核心发请求** → 核心经**进程间通信（IPC）**与相应服务器交互 → 服务器完成服务后经核心**回答**客户。

> [!note] 考点提示
> 微内核中服务之间**不直接互相调用**，一律走消息传递（IPC）——这正是练习 Q4 中错误选项"功能代码可以互相调用，性能很高"的出处。

## 鸿蒙操作系统（HarmonyOS）

### 四层架构

鸿蒙整体采用**分层的层次化设计**，从下向上依次为：

**内核层 → 系统服务层 → 框架层 → 应用层**

- 系统功能按"**系统**"-"**子系统**"-"**功能/模块**"逐级展开
- 多设备部署场景下，支持根据实际需求**裁剪**某些非必要的子系统或功能/模块

内核层组成（常考）：

| 组成 | 内容 |
|---|---|
| **KAL（内核抽象层）** | 为上层屏蔽内核差异 |
| **内核子系统** | **Linux Kernel、LiteOS**、…… |
| **驱动子系统 HDF** | HarmonyOS 驱动框架 |

### 四技术特性

| # | 特性 | 要点 |
|---|---|---|
| 1 | **分布式架构**首次用于终端 OS，实现跨终端无缝协同体验 | 4 大能力：**分布式软总线、分布式数据管理、分布式任务调度、虚拟外设**；屏蔽分布式底层技术难点，"像开发同一终端一样开发跨终端分布式应用" |
| 2 | **确定时延引擎 + 高性能 IPC**，实现系统天生流畅 | 任务执行前分配任务执行**优先级及时限**进行调度，优先级高的任务资源优先保障；应用响应时延**降低 25.7%**；微内核结构小巧使 IPC 效率较现有系统**提升 5 倍** |
| 3 | 基于**微内核架构**重塑终端设备可信安全 | 更强的**安全特性**和**低时延**；保证"**正确的人，通过正确的设备，正确地使用数据**"：分布式多端协同身份认证（正确的人）＋构筑可信运行环境（正确的设备）＋数据分类分级管理（正确地使用数据） |
| 4 | **统一 IDE** 支撑**一次开发，多端部署** | 实现跨终端生态共享 |

> [!warning] 易错点
> - 真题常把"**微内核**"篡改为"**宏内核**"制造错误选项（见练习 Q5、Q10）
> - 四层从下向上的顺序不能颠倒：**内核层 → 系统服务层 → 框架层 → 应用层**
> - 分布式 4 大能力中"虚拟外设"＝选项里常见的"分布式设备虚拟化"，是同一概念的不同说法
