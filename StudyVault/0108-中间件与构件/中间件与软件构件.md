# 中间件与软件构件

> [!note] 考情（大纲 1.3.6 / 1.3.7）
> 大纲补漏考点：**中间件**的定义/作用/类型/典型产品（IBM MQSeries、BEA Tuxedo）；**软件构件**的定义/作用、组装模型、三大商用构件标准规范（CORBA、J2EE、DNA 2000）。讲义第一章正文未覆盖，本节全部取自官方教程 §2.3.6–2.3.7。

## 一、中间件（§2.3.6）

### 定义与作用

**中间件（Middleware）** 是作为**应用软件与各种操作系统之间**使用的**标准化编程接口和协议**的一类软件，起**承上启下**的作用：使应用软件的开发相对**独立于计算机硬件和操作系统**，并能在不同的系统上运行，实现相同的应用功能。

- 中间件是**基础软件**的一大类，属于**可复用软件**的范畴。
- 位置：处在**操作系统、网络和数据库之上，应用软件之下**。
- 也有人认为中间件应属于**操作系统的一部分**。

> [!tip] 一句话记忆
> 中间件 = 应用与操作系统之间的"标准化接口和协议"，作用是**承上启下、屏蔽平台差异**。

### 中间件分类（按职责，8 类）

| 类型 | 职责 | 关键特征 / 代表产品 |
|---|---|---|
| 通信处理（**消息**）中间件 | 跨平台可靠、高效、实时数据传输 | **销售额最大**；BEA eLink、**IBM MQSeries**、TongLINK |
| 事务处理（**交易**）中间件 | OLTP 大量事务多机协调、故障恢复、负载平衡 | **BEA Tuxedo**（增长率最高的厂商） |
| 数据存取管理中间件 | 数据集中存放、虚拟缓冲存取、格式转换、解压 | 关系型/复合文档型/多媒体型 |
| Web 服务器中间件 | 弥补浏览器会话能力差、不擅长写入、受 HTTP 限制 | SilverStream |
| 安全中间件 | 军事/政府/商务上网的安全保密 | 需用国产产品 |
| 跨平台和架构的中间件 | 集成各节点不同平台的构件 | **CORBA**（功能最强，跨任意平台但庞大）；**JavaBeans**（灵活简单，适合浏览器）；**COM+**（适合 Windows） |
| 专用平台中间件 | 特定应用领域参考模式、配置构件库 | 电子商务、网站 |
| 网络中间件 | 网管、接入、网络测试、虚拟社区、虚拟缓冲 | 当前**最热门**研发项目 |

> [!important] 高频辨析
> - **销售额最大** → 消息中间件；**增长率最高厂商** → BEA Tuxedo（交易中间件）。
> - 三大跨平台构件技术：**CORBA 跨任意平台（最庞大）**、JavaBeans 灵活适合浏览器、COM+ 只适合 Windows。

### 典型产品

**1）IBM MQSeries（消息中间件）**
- IBM 的**消息处理中间件**，提供工业标准、安全、可靠的**消息传输系统**。
- 基本由**一个信息传输系统 + 一个应用程序接口**组成，其**资源是消息和队列**。
- 关键功能：**确保信息的可靠传输**；**异步消息处理**保证网络/应用"忙"或故障时信息**不丢失、不阻塞**。
- 支持所有主要计算平台和通信模式，支持 Internet、Java，拥有 Lotus Notes、SAP/R3 等接口。

**2）BEA Tuxedo（交易中间件）**
- 作为**电子商务交易平台**，属于**交易中间件**。
- 允许客户机和服务器参与**多个数据库协调更新**的交易，确保**数据完整性**。
- 特色：保证**不间断访问**；持续监视构件故障并从逻辑上排除、恢复；按负载指示自动开启/关闭应用服务，**均衡负载**。
- **DDR（数据依赖路由）**：按消息上下文选择路由；**交易队列**：异步"少连接"协同；**LLE 安全机制**：确保数据保密性。
- 应用/交易管理接口为 **50 多种硬件平台和操作系统**提供一致的 API。

## 二、软件构件（§2.3.7）

### 构件定义与特性

**构件（组件）** 是一个**自包容、可复用**的程序集（一组程序的集合，可体现为源程序或二进制代码）。该集合整体向外提供**统一的访问接口**，构件外部**只能通过接口访问**构件，**不能直接操作构件内部**。

> [!important] 两大最重要特性
> **自包容** 与 **可重用**。

### 构件组装模型

利用构件进行**搭积木式开发**：需求分析定义功能后，对构件**组装结构**进行设计，将系统划分成一组构件集合并明确构件间关系；构件**独立完成**（可新开发、可重用已有、可购买第三方），构件间**通过接口相互协作**。

**开发过程**：设计构件组装 → 建立构件库 → 构建应用软件 → 测试与发布。

**优点**：
- 自包容性让系统**扩展更容易**；
- 设计良好的构件更易被**重用，降低开发成本**；
- 构件粒度较整个系统更小，**安排开发任务更灵活**，可分组**并行独立开发**。

**缺点**：
- 构件设计需**经验丰富的架构设计师**，设计不良会**降低重用度**；
- 考虑重用度往往对**性能**等其他方面让步；
- 要求程序员**熟练掌握构件**，**增加学习成本**；
- **第三方构件库质量**影响最终软件质量，且**难以控制**。

### 三大商用构件标准规范对比

| 规范 | 提出方 | 平台 / 语言 | 核心内容 |
|---|---|---|---|
| **CORBA** | OMG（对象管理组织） | 跨任意平台 | 三层：**ORB（软总线）+ 公共对象服务 + 公共设施**；CCM 含抽象构件模型、构件容器结构、配置打包规范 |
| **J2EE** | Sun | Java（跨平台） | 支持 **RMI + IIOP**；服务器端 Servlet、JSP、**EJB**；EJB=业务逻辑层中间件 |
| **DNA 2000** | Microsoft | Windows 2000 | 服务器端 **ASP、COM、Cluster**；DCOM/COM/COM+ 面向服务器端分布应用 |

**1）CORBA** — 分 3 层：
- 最底层**对象请求代理 ORB**：规定分布对象的定义（接口）和语言映射，实现对象间通信和互操作，是分布对象系统中的"**软总线**"；
- 中间层**公共对象服务**：并发、名字、事务（交易）、安全等服务；
- 最上层**公共设施**：定义构件框架，提供可直接为业务对象使用的服务。
- **CORBA CCM**（构件模型）3 项内容：①抽象构件模型；②构件容器结构；③构件的配置和打包规范。

**2）J2EE** — Sun 给出完整的基于 Java 的企业分布应用规范：
- 分布式互操作协议同时支持 **RMI（远程方法调用）和 IIOP（互联网内部对象请求代理协议）**；
- 服务器端构造形式包括 **JavaServlet、JSP、EJB**；
- **EJB** 给出服务器端分布构件规范（构件、构件容器接口、构件打包/配置标准）；**EJB 是业务逻辑层的中间件技术**，提供事务处理能力；
- EJB 的 Bean 分**会话 Bean（维护会话）和实体 Bean（处理事务）**；通常 Servlet 负责与客户端通信、访问 EJB，JSP 产生页面回传。

**3）DNA 2000** — Microsoft 在 Windows 2000 基础上的分布计算架构：
- 服务器端提供 **ASP、COM、Cluster** 等应用支持；融合事务处理、可伸缩性、异步消息队列、集群；
- **DCOM/COM/COM+** 仍采用普通构件对象模型 **COM**；COM 最初是桌面系统构件技术（为 OLE 服务），随 Windows NT 和 **DCOM** 发布延伸到分布应用领域；
- 通过 **COM+** 服务设施（**负载均衡、内存数据库、对象池、构件管理与配置**）把 COM、DCOM、**MTS（微软事务处理服务器）** 统一成功能强大的构件应用架构。

> [!warning] 易错点
> - **CORBA 是跨任意平台**（功能最强但庞大）；**COM+/DNA 只适合 Windows**；**JavaBeans/EJB 跨平台**。
> - **EJB ≠ JavaBeans**：EJB 提供事务处理能力，是业务逻辑层中间件。
> - ORB 的别称是"**软总线**"，别答成硬件总线。
