# 进程、线程、PCB 与三态模型

## 进程的概念

★ 进程是**程序在一个数据集合上运行的过程**，是系统进行**资源分配和调度**的独立单位。

组成 = **程序块 + 进程控制块（PCB）+ 数据块**。

★ 进程的 2 个基本属性：
- 可拥有资源的独立单位
- 可独立调度和分配资源的基本单位

> [!important] PCB 是进程存在的唯一标志
> PCB 内容：进程标识符、状态、位置信息、控制信息、**队列指针**（链接同一状态的进程）、优先级、现场保护区等。系统通过 PCB 感知和管理进程。

## 进程 vs 线程

| 对比 | 进程 | 线程 |
|---|---|---|
| 资源 | 拥有资源的独立单位 | 基本不拥有资源，共享进程资源 |
| 调度 | 独立调度单位 | 独立调度的基本单位（更轻量） |
| 共享 | — | 共享进程的代码、数据、**已打开文件** |
| 私有 | — | **栈指针、寄存器**私有 |

> [!warning] 易错点（真题）
> 同一进程的线程间：**已打开文件可共享；栈指针不可共享**。
> 真题"T1 的栈指针不能被 T2 和 T3 共享" → 选 **C**。

## 进程的三态模型

```
        调度(获得CPU)        时间片完/被抢占
  就绪 ───────────→ 运行 ───────────→ 就绪
   ↑                  │
   │ 事件发生          │ 等待事件
   │ (I/O完成)         ↓
   └──────────────  阻塞
   （阻塞→就绪：事件发生；阻塞不能直接→运行）
```

- ☐ **运行**：在 CPU 上运行（单处理机同时只有一个运行态进程，多进程交替运行）
- ☐ **就绪**：获得**除 CPU 外**的一切所需资源，一旦得到处理机即可运行
- ☐ **阻塞**（等待/睡眠）：等待某事件发生（请求 I/O、等 I/O 完成）而暂停；**即使把 CPU 分配给它也无法运行**

> [!tip] 状态转换判断
> - 就绪→运行：被调度
> - 运行→就绪：时间片完 / 被更高优先级抢占
> - 运行→阻塞：主动等待事件（请求 I/O）
> - 阻塞→就绪：等待的事件发生
> - ⚠ **阻塞不能直接到运行**，必须先到就绪排队

## PCB 的组织方式

| 方式 | 说明 |
|---|---|
| 顺序方式 | PCB 连续存放，靠下标找 |
| 链接方式 | 同状态 PCB 用队列指针链成队列 |
| 索引方式 | 按状态建**索引表**，表目指向对应 PCB |

> [!important] 真题图核对
> 讲义原图为三张**索引表**（运行/就绪/阻塞进程索引表），表目指针指向 PCB1–PCB9 → 组织方式 = **索引方式**；计数 = 运行 2、就绪 3、阻塞 4。
