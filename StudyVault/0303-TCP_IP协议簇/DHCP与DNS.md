# DHCP 与 DNS

## DHCP：动态主机配置协议

DHCP（Dynamic Host Configuration Protocol）：为主机动态分配 IP 地址，**基于 UDP**（服务端 67 / 客户端 68 端口），采用**客户机/服务器模型**。

三种分配方式：

| 方式 | 说明 |
|---|---|
| 固定分配 | **管理员分配** |
| 动态分配 | 分配**有效期限**的 IP 地址 |
| 自动分配 | 分配**无限长**的 IP 地址 |

无效地址：**169.254.X.X** 和 **0.0.0.0**（169.254 是 DHCP 故障时 Windows 分配的自动专用 IP，见 [[IP-TCP-UDP]]）。

## DHCP 报文流程

标准流程四步（**DORA**）：

1. **DHCP 发现（DISCOVER）**：客户端广播寻找可用的 DHCP 服务器
2. **DHCP 提供（OFFER）**：服务器向客户端提供 IP
3. **DHCP 请求（REQUEST）**：客户端正式请求接受该地址
4. **DHCP 确认（ACK）**：服务器确认，分配完成

另有三种非常规报文：

| 报文 | 方向 | 含义 |
|---|---|---|
| **DhcpNack** | 服务器 → 客户端 | 服务器拒绝客户端 |
| **DhcpDecline** | **客户端 → 服务器** | 客户端拒绝接受已分配的地址（如地址已被其他客户端使用） |
| **RELEASE** | 客户端 → 服务器 | 客户端释放地址 |

租约规则：

- 租约**默认 8 天**
- 租约**过半（50%）**时，客户机需向 DHCP 服务器申请**续租**
- 租约超过 **87.5%** 仍未与当初提供 IP 的 DHCP 服务器联系上，则开始**联系其他的 DHCP 服务器**

> [!warning] 题眼：Decline vs Nack（讲义 p15 题）
> 地址已被别的客户端占用时，由**客户端**向服务器发 **DhcpDecline** 拒绝接受；**Nack** 才是**服务器**端的拒绝。方向相反，别混。

> [!note] 32h 补充
> 网络中可能有多个 DHCP 服务器，各自负责不同网段，也可能一个服务器负责多个网段；若多个 DHCP 服务器都发送 OFFER 报文，**客户端只根据第一个收到的 OFFER 报文返回 REQUEST**。（32h p24）

## DNS：域名系统

DNS（Domain Name System）：把主机**域名解析为 IP 地址**，基于 UDP 53 端口，记录域名与 IP 的映射关系。

### 递归查询 vs 迭代查询

| 查询方式 | 定义 |
|---|---|
| **递归查询** | 服务器**必须回答**目标 IP 与域名的映射关系——要求服务器彻底完成名字解析，返回最后的结果 |
| **迭代查询** | 服务器收到一次迭代查询就回复一次结果；结果**不一定是目标 IP 与域名的映射，也可以是其他 DNS 服务器的地址**，本地服务器再访问被引用的服务器继续查询 |

默认规则（题眼）：

- **主机 → 本地域名服务器：递归查询**
- **本地域名服务器 → 根域名服务器：通常采用迭代查询**
- 若本地域名服务器向根也采用递归查询：根域名服务器**负担重、效率低，故较少采用**

> [!warning] 讲义 p18 题眼
> 题目图中查询请求从根域名服务器继续向下级联到中介、授权域名服务器 → 说明**根采用了递归查询**；"不合理"之处即"**根域名服务器采用递归查询，影响了性能**"（选 A）。一句话记忆：**根服务器只用迭代，根用递归 = 影响性能**。

### PTR 反向解析

DNS 正向解析是域名 → IP；**PTR（Pointer Record）负责将 IP 地址映射到域名的反向解析**。

典型故障场景（讲义 p19 题）：nslookup 查询服务器**名称**能解析出 IP，反过来查 **IP 却解析不出名称** → 反向解析缺记录，解决方法是**为该服务器创建 PTR 记录**（不是清缓存、不是重启服务）。

### Linux DNS 配置：resolv.conf

Linux 系统中 DNS 的配置文件是 **/etc/resolv.conf**，包含主机的域名搜索顺序和 DNS 服务器的地址。四个关键字：

| 关键字 | 作用 |
|---|---|
| **nameserver** | 定义 DNS 服务器的 IP 地址 |
| **domain** | 定义本地域名 |
| **search** | 定义域名的搜索列表 |
| **sortlist** | 对返回的域名进行排序 |

> [!tip] 记忆口诀
> "**名（nameserver）域（domain）搜（search）排（sortlist）**"。

> [!tip] 来源：32h p24（PTR 定义、多 OFFER 取第一个）
