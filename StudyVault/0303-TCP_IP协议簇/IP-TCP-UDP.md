# IP、TCP 与 UDP

> [!info] 考情
> 本章考情：基本概念 1 + 交换技术 2 + **TCP/IP 3** + 5G 1 + 云计算 2 = 9 分，**TCP/IP 协议簇是本章最重的考点（3 分）**。

## TCP/IP 分层模型

TCP/IP 为四层结构，与 OSI 七层模型的对应关系：

| TCP/IP 模型 | OSI 七层模型 |
|---|---|
| 应用层 | 应用层、表示层、会话层 |
| 传输层 | 传输层 |
| 网际层 | 网络层 |
| 网络接口层 | 数据链路层、物理层 |

**网际层是整个 TCP/IP 体系结构的关键部分**，其功能是使主机可以把分组发往任何网络并使分组独立地传向目标。

各层协议（协议栈框图）：

- **应用层**：POP3(110)、FTP(20/21)、Telnet(23)、HTTP(80)、SMTP(25)、NFS、DHCP(67)、TFTP(69)、SNMP(161)、DNS(53)
- **传输层**：TCP、UDP
- **网际层**：IP、ICMP、IGMP、ARP、RARP
- **网络接口层**：CSMA/CD、TokenRing（以太网、令牌环）

## 常用协议与端口号

| 协议 | 端口 | 说明 |
|---|---|---|
| POP3 | 110 | 邮件**收取** |
| SMTP | 25 | 邮件**发送** |
| FTP | 20 数据端口 / 21 控制端口 | 文件传输协议 |
| HTTP | 80 | 超文本传输协议，网页传输 |
| HTTPS | 443 | HTTP 加入 SSL/TLS 后的安全网页协议 |
| DHCP | 67（服务端）/ 68（客户端） | IP 地址自动分配 |
| TFTP | 69 | 不可靠的、开销不大的小文件传输协议（UDP） |
| SNMP | 161（轮询）/ 162（陷阱） | 简单网络管理协议 |
| DNS | 53 | 域名解析协议，记录域名与 IP 的映射关系 |
| Telnet | 23 | 远程连接（登录）协议 |

网际层协议一句话定位：

- **TCP**：可靠的传输层协议；**UDP**：不可靠的传输层协议
- **ICMP**：因特网控制协议，**PING 命令来自该协议**（传递"网络通不通、主机是否可达、路由是否可用"等控制消息）
- **IGMP**：组播协议（允许主机参加多播）
- **ARP**：IP 地址 → MAC 地址；**RARP**：MAC 地址 → IP 地址

> [!warning] 题眼（讲义 p9 原话）
> **TCP 协议可以依据端口号将报文交付给上层的某一进程，可以对应用层进程进行寻址。**（讲义 p11 题直接考这句 → 选"对应用层进程的寻址"）

> [!tip] 来源：一本通 p78 端口对照表 / 32h p24（HTTPS 443、DHCP 67/68、SNMP 161/162）

## TCP vs UDP

| 维度 | TCP | UDP |
|---|---|---|
| 全称 | 传输控制协议 | 用户数据报协议 |
| 连接 | **面向连接** | **无连接** |
| 可靠性 | **可靠**：在 IP 不可靠数据基础上采用**重发技术**，差错校验和重传、流量控制、拥塞控制 | **不可靠** |
| 特点 | 全双工的端到端服务 | 有助于提高传输速率 |
| 适用场合 | 数据量**比较少**、对**可靠性要求高** | 数据量**大**、可靠性要求不高、要求**速度快** |
| 典型应用 | FTP、HTTP、SMTP、Telnet（均可靠传输） | DHCP、DNS、TFTP、SNMP/NFS（均不可靠传输） |

> [!tip] 记忆口诀
> "**TCP 少而可靠，UDP 多快而糙**"。两者**共同**的能力只有**端口寻址**（连接管理、差错校验重传、流量控制都是 TCP 独有，见练习 Q8）。

> [!tip] 来源：一本通 p77-78 / 32h p25

## IP 协议

IP 是网络层（网际层）**最重要的核心协议**：在源地址和目的地址之间传送数据报，**无连接、不可靠**。

## IP 地址分类（分类编址）

机器中存放的 IP 地址是 **32 位二进制代码**，通常用**点分十进制**表示：每 8 位转成十进制（每段取值 **0~255**），段间加"."，如 128.11.3.31。

逻辑上 32 位分为**网络号 + 主机号**，按网络号位数分类：

| 类别 | 首字节范围 | 首比特 | 地址范围 | 备注 |
|---|---|---|---|---|
| A 类 | 0~127 | 0 | 0.0.0.0 ~ 127.255.255.255 | 网络号 8 位 |
| B 类 | 128~191 | 10 | 128.0.0.0 ~ 191.255.255.255 | 网络号 16 位 |
| C 类 | 192~223 | 110 | 192.0.0.0 ~ 223.255.255.255 | 网络号 24 位 |
| D 类 | 224~239 | 1110 | 224.0.0.0 ~ 239.255.255.255 | **组播** |
| E 类 | 240~255 | 1111 | 240.0.0.0 ~ 255.255.255.255 | **保留** |

主机位规则：**全 0 = 本网络地址，全 1 = 广播地址**，其他才是主机地址。

> [!tip] 记忆口诀
> 首字节分界 "**127 / 191 / 223 / 239 / 255**"，比特前缀 "**0、10、110、1110、1111**" 逐位加 1。

## 特殊 IP 地址

**公有地址**：由 Inter NIC 分配，全网唯一，直接访问因特网。
**私有地址**：非注册地址，组织内部使用、可重复使用、**不能直接访问因特网**：

| 类别 | 范围 | 网络数 |
|---|---|---|
| A | 10.0.0.0 ~ 10.255.255.255 | 1 |
| B | 172.16.0.0 ~ 172.31.255.255 | 16 |
| C | 192.168.0.0 ~ 192.168.255.255 | 256 |

其他特殊地址：

| 网络号 | 主机号 | 含义 |
|---|---|---|
| 0 | 0 | 本网络上的本主机（仅作源地址） |
| 全 1 | 全 1 | 在本网络上广播（仅作目的地址） |
| Net-ID | 全 1 | 对 Net-ID 上的所有主机广播 |
| 127 | 非全 0/全 1 | **本地软件环回测试**（如 ping 127.0.0.1 检查 TCP/IP 协议） |
| 169.254 | 非全 0/全 1 | **自动专用 IP**：Windows 主机 DHCP 服务器故障时分配的临时地址 |

## 子网划分（VLSM）

分类编址不实用（各类主机数相差太大、地址空间利用率低、两级地址不灵活）→ **将主机号拿出几位作为子网号**，IP 地址变为三级结构：**网络号 + 子网号 + 主机号**（本质仍保留分类编址结构）。

- **子网掩码**：网络号和子网号位全为 1，主机号位全为 0
- 判断同网段：子网掩码与源 IP 做**与运算**得出**网络地址**，网络地址相同即同一网段；网络号不同的主机必须经过路由才能通信
- 计算要点：**子网号可以全 0、全 1；主机号不能全 0 或全 1 → 可分配主机数要 −2，子网数不用减**
- 划分子网后若还需继续划分，可再向主机号借位，即**可变长子网掩码（VLSM）**——都是向主机号借位

## 无分类编址 CIDR

无分类编址**完全忽略分类编址**，按需自定义网络号与主机号位数（总长仍 32 bit）。

- 格式：**IP 地址/网络前缀位数**，如 `128.168.0.11/20`：网络号占 20 位，主机号 = 32 − 20 = 12 位
- 题眼：**"/"后的数字是网络号位数，32 减去它就是主机号位数**
- **路由汇聚**：选择多个网段网络地址中**相同的位**作为汇聚后的网络号，**不同的位划入主机位**，把多个网段汇聚成一个超网。可理解为子网划分的**逆过程**：子网划分不断向主机位借位（子网变多、主机变少）；汇聚则缩小子网数量、增加网络内主机数量
- **最佳路由匹配原则（最长前缀匹配）**：路由表可能匹配出多条结果，选**网络前缀最长**的路由（前缀越长地址块越小、路由越具体）

> [!tip] 来源：一本通 p83-85

## IPv6 与过渡技术

IPv6 主要为解决 IPv4 地址数不够用而提出，特性：

- 地址长度 **128 位**，地址空间增大 **2^96 倍**
- 灵活的报文头部：用一系列**固定格式的扩展头部**取代 IPv4 可变长度选项字段，路由器可快速掠过选项不做处理，加快报文处理
- 简化头部格式 → 加快转发、提高吞吐量
- 提高安全性：**身份认证和隐私权是 IPv6 的关键特性**
- 支持更多服务类型；允许协议继续演变
- IP 数据报目的地址有三种：**单播、多播/组播、任播**

**IPv4 → IPv6 过渡的三种基本技术**：

| 技术 | 机制 |
|---|---|
| **双协议栈** | 主机**同时运行 IPv4 和 IPv6 两套协议栈**；两地址间存在转换关系，如 IPv6 的低 32 位可直接转换为 IPv4 地址，实现互通 |
| **隧道技术** | 在 IPv4 网络之上建立传输 IPv6 数据报的隧道：把 IPv6 数据报当作 IPv4 数据报的**数据部分加以封装**，只加一个 IPv4 首部即可在 IPv4 网络中传输 |
| **翻译技术（NAT-PT）** | 用专门的翻译设备（如转换网关）在纯 IPv4 与纯 IPv6 网络之间**转换 IP 报头地址并做语义翻译**，使两类站点透明通信 |

> [!warning] 易混点
> "双协议栈"是**两套协议并行运行**（一台主机两个栈）；"隧道"是**封装**（IPv6 报文装进 IPv4 数据部分）。选项里常把二者机制张冠李戴。

> [!tip] 来源：一本通 p85-86 / 32h p24（任播、NAT-PT 名称）
