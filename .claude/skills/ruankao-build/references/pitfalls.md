# 实战经验（第二~四章踩坑沉淀）

新会话建章前通读一遍。均为已验证事实，非猜测。

## 讲义源性状

1. **讲义可能多 PPT 拼接**：第三章讲义含两个封面/两套提要，L1 序列会出现重复主节；骨架按主节合并同主题页，不按 PPT 切。
2. **讲义正文可能缺主节**：第四章提要列 5 主节（概述/设计阶段/关系代数/规范化/数据控制），正文只讲 3 个"掌握"级；"了解"级主节（数据库概述/设计阶段）正文缺失。骨架仍给缺失主节留文件夹，主体靠官方/一本通/案例补，并标"讲义仅提要"。
3. **考情表位置不定**：第二、三章在主讲义 p2/p3；第四章在案例特训 PDF 的 p3（案例题年表，25 分/年）。步骤 0 把考情表找到读掉再划骨架。

## 扫描书

4. **目录缓存与实际内容会错位**：一本通目录缓存"六 p75-90"，实际 p75 是五篇数据库尾部（INTERSECT 等）。抽取以首图内容定性起点；错位页内容归还原 chapter 复用（p75 留给第四章）。
5. **一本通目录缓存无小节**（五/六篇只有整篇范围）：对齐表写到整篇级，抽取后按页内标题做主题对齐。

## 官方书补肉

6. **先 --kw 找集中区间再 --extract**；别按章节直觉：云计算在 §11.6 不在 §17；5G 在 §17.2.3 不在 §17.3。同一知识点可能多处零星（p612/p648），取集中区。
7. **官方书也缺应试内容**：AI 芯片、交换技术部分官方无独立小节 → 讲义为准标"无旁证，考试跟讲义"。

## subagent 协作

8. **prompt 里给"如实报告"出口**：agent 会报"来源与预设出入""OCR 损坏数字未采用""防火墙层次官方未明说采用 32h 口径"。收结果先看偏离说明，再决定改笔记还是改 mapping。
9. **合并前校验页覆盖**：merge 脚本必打印缺页列表；有缺页回派对应区间 agent，不静默跳过。

## 用户协作

10. **骨架划分跟讲义主节**（用户否决过自拟 7 夹方案）；过目环节不可省。
11. **dashboard 统计数字用户自己维护**：只加 ⬜ 行，不改他的数字；他会重排表格/改文件名，编辑前 Read 当前版。
12. **JSON 中文键、文件夹禁 `/`、concepts 同号**：用户明确要求过。
